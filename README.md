# ACM Template

ACM Template 是一个记录了 ACM 相关的算法模板的代码仓库，旨在将算法抽象成可训练记忆的标准化组件，从而提高比赛的效率。

## 代码规范

良好的代码规范非常重要，对于 ACM Template，我们遵循如下代码规范和约定：

- 环境**统一使用 Linux 系统**，发行版不限。
- 编译器统一 G++ 13.2.0 或以上，使用 **C++20** 的语言规范，**激进地使用 GNU 扩展**，如 pbds 来简化心智负担。
  - 例如，永远使用 `__gnu_pbds::tree` 来替代 `std::set` / `std::map`。
  - 始终使用扩展万能头 `#include <bits/extc++.h>`
- **缩进统一使用四个空格**。
- 变量，运算符之间必须要加空格，目的是增强可读性，例如：

```c++
int a, b = 3, c = 4; // 逗号后面加空格
a = b + c;           // 变量，运算符之间加空格
for (int i = 0; i < a; i++) { // 对于 if / for statement，在关键词后加空格
    // do something in a loop...
}
```

- **永远不应该** `using namespace`，防止污染命名空间。
- 命名规范的核心宗旨是在简短的同时保持优秀的可读性
  - 函数名，类型名均要求大驼峰，如 `SegTree`，`PushUp()` 等。
  - 变量名要求精简但符合惯例，在**不产生二义性**的情况下尽可能单字母
    - 例如对于图论中对于顶点，边权的命名，我们一般用 `u`，`v`，`w`，有时也用 `s`，`t` 描述起点和终点
- 大括号规范遵循 Go 语言的标准，即将起始大括号压缩到上一行的末尾，以下是示范

```c++
if (a < b) {
    for (int i = 0; i < a; i++) {
        // do something in a loop...
    }
    // do something...
} else {
    // do something else...
}
```
  
- 对于单行的 if / for statement，我们默许激进地取消大括号，也允许激进地合并小语句到同一行，但不宜过长。
  - 如何判定过长：当长度超过人眼认为的视觉平衡，即“看起来怪怪的”时，就可以换行了。
- 对于自增语句，我们允许在不产生二义性的情况下，使用诸如 `a = ++b` 之类的语句。
- 在涉及位运算和常规运算混合的场景下，我们的原则是：只加必要的括号，默认并且充分地信任选手都具备运算优先级的知识。
- 对于小函数，永远加 `inline` 优化。
- 激进地使用 `constexpr`，`consteval`，`constinit` 来进行编译期优化。
